# Моніторинг контейнеризованого проєкту в Azure (Prometheus & Grafana)

Цей розділ проєкту присвячений організації повноцінного моніторингу інфраструктури та застосунку, розгорнутих у хмарі Microsoft Azure. Система дозволяє в реальному часі спостерігати за станом сервера, завантаженням ресурсів та роботою Docker-контейнерів.

## 1. Як розгортається моніторинг

Розгортання системи моніторингу повністю автоматизоване і відбувається за принципом **Infrastructure as Code (IaC)**:

1. **Terraform:** Створює необхідну хмарну інфраструктуру в Azure та відкриває порти для доступу до панелей моніторингу.
2. **cloud-init:** Під час ініціалізації віртуальної машини автоматично встановлює Docker та запускає два стеки: основний застосунок та стек моніторингу.
3. **Docker Compose:** Використовується окремий конфігураційний файл `docker-compose.monitoring.yml`, який оркеструє роботу чотирьох взаємопов'язаних сервісів.

**Команда для розгортання:**
` ` `bash
cd infra/terraform
terraform apply -auto-approve
` ` `

## 2. Сервіси, що збирають метрики

Для забезпечення повного огляду системи (Observability) використано наступні компоненти:

* **Prometheus:** Центральне ядро системи, яке опитує (scrape) джерела метрик, зберігає дані у часових рядах та надає їх для візуалізації.
* **Node Exporter:** Агент, що працює безпосередньо на Linux-хості та збирає апаратні метрики (CPU, RAM, Disk, Network).
* **cAdvisor (Container Advisor):** Аналізує роботу Docker-контейнерів, збираючи дані про споживання ресурсів кожним окремим сервісом.
* **Grafana:** Платформа для візуалізації, яка підключається до Prometheus і відображає отримані дані на графічних дашбордах.

## 3. Відкриті порти

У налаштуваннях Azure Network Security Group (NSG) було відкрито наступні порти для зовнішнього доступу:

| Порт | Сервіс | Призначення |
| :--- | :--- | :--- |
| **3000** | Grafana | Веб-інтерфейс для перегляду графіків та дашбордів |
| **9090** | Prometheus | Веб-інтерфейс бази даних метрик та перевірка статусів (targets) |
| **5000** | Web App | Доступ до основного застосунку проєкту |
| **22** | SSH | Віддалене керування сервером |

## 4. Як відкрити Grafana

Після завершення розгортання та успішного виконання `terraform apply`:

1. Скопіюйте значення `public_ip_address` з виводу термінала.
2. Перейдіть у браузері за адресою: `http://<ВАША_IP_АДРЕСА>:3000`.
3. Для входу використайте стандартні облікові дані:
   * **Логін:** `admin`
   * **Пароль:** `admin` (система запропонує змінити його при першому вході).
4. Переконайтеся, що в розділі **Data Sources** підключено Prometheus за адресою `http://prometheus:9090`.

## 5. Створені панелі моніторингу

У системі налаштовано два основні дашборди для комплексного аналізу:

1. **Node Exporter Full (ID: 1860):**
   * Відображає загальний стан "здоров'я" віртуальної машини.
   * Основні показники: завантаження ядер процесора, використання оперативної пам'яті, вільне місце на дисках та інтенсивність мережевого трафіку.
2. **Docker Container Monitor:**
   * Дозволяє детально аналізувати роботу кожного окремого контейнера (`web`, `db`, `prometheus` тощо).
   * Основні показники: ліміти пам'яті по кожному контейнеру, завантаження CPU контейнером та статус роботи (uptime).

---
**Важливо:** Після завершення роботи з моніторингом не забудьте видалити ресурси командою `terraform destroy`, щоб уникнути зайвих витрат у хмарі Azure.
